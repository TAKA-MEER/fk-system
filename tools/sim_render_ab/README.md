# 描画の切り分け A・B（WP-SIM-11。差し戻し後の再集計）

単盤 P004 の盤前の認識し直しで、ss が近くの吊り金具を時々拾えない（`top_not_found`）。
**描画が原因か（艶の無い灰色どうし・金属を拡散寄りに潰す `Renderer`）、検出器が原因か**を、
基準／A（金具の見た目だけ変更）／B（Cycles）を同じ姿勢・同じノイズの種で比べる道具。

## 結論（見立て。見逃しを (a)(b) に分けて書く）

見逃しは 2 種類あり、原因が違います。

- **(a) 画角の縁で切れている金具**（リング中心が縁から投影半径 76 px 未満）。**どの描き方でも落ちます**
  （Cycles でも 19/20・6/20）。これは描画ではなく、近くの金具が「大きくて縁に半分外れた」姿そのものが
  検出器の条件から外れていることです。
- **(b) 金具がまるごと画面の中なのに落ちる**。基準（pyrender）は 8〜16/20 の種で取りこぼすのに、
  **Cycles は 20/20 で全部見つけます**。A の色・艶の変更は効きません（暗い色は 0/20、艶は 3〜17/20、明るいは 9〜20/20）。
  つまり (b) は **pyrender の描き方の質が原因**で、金具の色・艶を変えても直りません。
  ss に渡った実際の失敗の絵（大きくはっきり写っているのに 0 件）は (b) の姿です。

WP-SIM-10 の時点の数（立ち位置を誤って 4.389 m としていた）は (a) が支配的で、「描画が原因」には
見えませんでした。正しい立ち位置（4.489 m）にヨーの振りを加えて取り直すと、上記のとおり
(b) が pyrender の描画の質に寄ることが分かりました。

## 道具

描画はコンテナ（像 `fk-sim`、GPU 無し。ROS は使わないので `ROS_DOMAIN_ID` は出さない）、
検出はホスト（lifting-lug-pose の venv の `Detector`）。

```
python tools/sim_render_ab/build_scenes.py          # A の 3 通りのシーンと B 用 .blend を作る（ホストの Blender で）
python tools/sim_render_ab/run_all.py               # 基準・A の pyrender、Cycles、後処理（最後は検出コマンドを出す）
<venvpython> tools/sim_render_ab/detect.py --frames-root sim_out/sim_render_ab/frames --scene sim_out/scenes/public_room
<venvpython> tools/sim_render_ab/collect_representative.py --frames-root sim_out/sim_render_ab/frames --scene sim_out/scenes/public_room --out sim_out/sim_render_ab/representative
```

- `appearance.py`: 姿勢（`fk_auto.core.stand_pose` + ss の `scan_plan` を読み取りで import）・近い／遠いの振り分け・15 px の突き合わせ・見逃しの (a)(b) の境。前提の純関数。
- `render_frames.py`: pyrender の描画（容器。基準・A）。
- `make_cam_mats.py` + `cycles_render.py` + `post_cycles.py`: Cycles の描画（ホストの Blender。歪ませ方と後処理は `Renderer` と同じ関数）。
- `detect.py`: 検出と表。`--only-kinds` で B と同じ姿勢だけに絞れる。`report.json` に姿勢×金具の全部の行を出す。
- `test/`: 上の純関数の試験（ホストで。既定で今と同じ値になることも縛る）。

表の数値・代表の絵は `sim_out/sim_render_ab/`（gitignore 済み）に残ります。

## 前提（差し戻しで直したもの）

1. 立ち位置の計算値は (3.0, **4.489**) です（北の面は幅の半分 0.6 m + 0.389 + 0.5）。記録 (3.0, 4.66) との差は 0.17 m です。
2. `Renderer` の既定（0.0・0.7）はモジュール定数 `DEFAULT_METALLIC`・`DEFAULT_ROUGHNESS` に出して試験で縛っています。
3. A 艶の `roughness_factor` は金具だけでなく**全部の材質に効きます**（金具だけに効く実装はしていません）。
4. Blender は `fk-sim` 像の中にありません。B はホストの Blender 4.2.7（FK-E1 と同じ版）で描き、歪ませ方と後処理だけコンテナで `Renderer` と同じ関数を通しました。
5. Cycles は密封した部屋では真っ暗になります（天井に太陽光・環境光が遮られる）。部屋の四隅に点光源（各 30 W）を足して描きました（平均輝度 pyrender 138 / Cycles 114）。pyrender の `ambient_light` は遮らないので完全な対等ではありません。
