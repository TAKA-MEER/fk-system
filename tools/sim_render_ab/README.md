# 描画の切り分け A・B（WP-SIM-11）

単盤 P004 の盤前の認識し直しで、ss が近くの吊り金具を時々拾えない（`top_not_found`）。
**描画が原因か（艶の無い灰色どうし・金属を拡散寄りに潰す `Renderer`）、検出器が原因か**を、
基準／A（金具の見た目だけ変更）／B（Cycles）を同じ姿勢・同じノイズの種で比べる道具。

## 結論（見立て）

**金具の色・艶を変えても近くの金具の見逃しは直らなかった（A は基準より悪い）。Cycles でも見逃しは残る（基準 0.633 → Cycles 0.767）。**
したがって「pyrender の材質の潰し方が主因」という仮説は支持されない。
一方 Cycles の方が良い（誤差中央値も 3.1 px と小さい）ので、描画の質は効いているが、
近くの大きくなった金具の取りこぼし自体は描き方を変えても無くならない。
**検出器側（近くの大きな金具の学習条件）の可能性が残る**。直すかどうかは結果を見てユーザーが決める（このパケットは調べるだけ）。

## 正解の縁の余裕（参考）

立ち位置（面から 0.889 m）・下向き 20°の段では、画像に入るのは遠い側の 2 金具だけで近い側は入らない。
下向き 38.2°・中央ヨーの段では、近い側の 1 金具だけが画角の**横の縁に半分外れた**状態で入る
（リング半径約 76 px に対し、中心の縁からの余裕は 24 px）。下向き 56.4°の段では 4 金具とも入らない。
下向き 38.2°でヨーを ±12°振ると、近い側の 1 金具が縁から 276〜322 px のところに収まる。
つまりこの距離では、近い金具は「大きくて縁に半分外れた」姿になりやすく、検出器の取りこぼしはこの姿に集中している。

## 前提の食い違い（ブリーフどおり報告）

1. **記録の位置 (3.0, 4.66) と `stand_pose` の計算値 (3.0, 4.389) は 0.27 m 違います。**
   計算は盤の北の面（中心から 0.5 m）+ `stand_distance_min_m` 0.389 + `stand_margin_m` 0.5 = 1.389 m。
   記録の 4.66 は北の面から 1.16 m のところにあります。原因は不明（th の停止誤差など）。
   本ツールでは計算の立ち位置を基準とし、記録の位置も別に 1 姿勢入れてあります。表は両方含みます。
2. **Blender は `fk-sim` 像の中にありません（`which blender` 無し）。**
   B はホストの Blender 4.2.7（FK-E1 と同じ版）で描き、歪ませ方と後処理だけコンテナで `Renderer` と同じ関数を通しました。
3. **Cycles は密封した部屋では真っ暗になります**（天井に太陽光・環境光が遮られる）。
   そのため部屋の四隅に点光源（各 30 W・柔らかい影）を足して描いています（`cycles_render.py` の `add_lights`）。
   pyrender の `ambient_light` は遮らないので、完全な対等ではありません。平均輝度は pyrender 138 / Cycles 114 と近い値にしました。
4. 「遠い 2 金具」は下向き 20° の段でしか画像に入らず、56.4° の段では 4 金具とも入りません
   （正解の投影で画像の中に入るものだけを数えています）。

## 道具

描画はコンテナ（像 `fk-sim`、GPU 無し。ROS は使わないので `ROS_DOMAIN_ID` は出さない）、
検出はホスト（lifting-lug-pose の venv の `Detector`）。

```
python tools/sim_render_ab/build_scenes.py          # A の 3 通りのシーンと B 用 .blend を作る（ホストの Blender で）
python tools/sim_render_ab/run_all.py               # 基準・A の pyrender、Cycles、後処理（最後は検出コマンドを出す）
<venvpython> tools/sim_render_ab/detect.py --frames-root sim_out/sim_render_ab/frames --scene sim_out/scenes/public_room
<venvpython> tools/sim_render_ab/collect_representative.py --frames-root sim_out/sim_render_ab/frames --scene sim_out/scenes/public_room --out sim_out/sim_render_ab/representative
```

- `appearance.py`: 姿勢（`fk_auto.core.stand_pose` + ss の `scan_plan` を読み取りで import）・近い／遠いの振り分け・15 px の突き合わせ。前提の純関数。
- `render_frames.py`: pyrender の描画（容器。基準・A）。
- `make_cam_mats.py` + `cycles_render.py` + `post_cycles.py`: Cycles の描画（ホストの Blender。歪ませ方と後処理は `Renderer` と同じ関数）。
- `detect.py`: 検出と表（`--only-kinds center,recorded` で B と同じ姿勢だけに絞れる）。
- `test/`: 上の純関数の試験（ホストで。既定で今と同じ値になることも縛る）。

表の数値・代表の絵は `sim_out/sim_render_ab/`（gitignore 済み）に残ります。
