# 関連システムとの衝突（検討メモ）

**spec ではない。**衝突の一覧の正は [Spec-open.md](spec/Spec-open.md) §1.1。ここは**ユーザーに決めてもらうこと**をまとめる。
2026-11-01 に th-system・hve-system の実装管理担当へ照会し、見解を受けた（どちらも私見で、相手側のユーザーの判断はまだ）。
中身は [conflicts-th.md](conflicts-th.md)・[conflicts-hve.md](conflicts-hve.md)。

## 結論

- **重いのは th-system 側。**地図より先に、**自律で続けて動くことそのもの**が th-system の 2 つの決まりとぶつかる。
  - th-system `Spec-onsite.md` §6「経路が決まったあとは自動で別のルートを探さない。探すのは試験員が『再検索』を押したときだけ」
  - th-system SD-8「試験員が押していないのにロボットが動き出す経路を作らない」
- hve-system 側は、**つなぎ方を選べば決まりを大きく変えずに済む見込み**（本システム・ss-system を上部モジュールとして繋がない。hve のすすめは形 1）。
  重いのは**押し当て方**（昇降機は自重で下がる）と、**ss-system がカメラの向きを知る手段が無いこと**。
- 本システムの読み違いが 1 件あった: hve-system `Spec-ui.md` の「使っている間は走行系を動かさない」は予備の高画質映像の帯域の話で、昇降との排他ではない（[Spec-open.md](spec/Spec-open.md) §1.1 を直した）。
