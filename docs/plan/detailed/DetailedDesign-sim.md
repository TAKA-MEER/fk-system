名前は [-names.md](DetailedDesign-names.md) §8（案）。確定するまで、この文書の名前で実装しない。

## 0. 結論

| 項目 | 案 |
| --- | --- |
| 元になる記述 | **盤・部屋・障害物・機体の置き場を 1 つの YAML（シーンの記述）に書く**（§2）。現場再現版と広報版は、この記述が違うだけ |
| 作るもの | 記述から **(a) Gazebo のワールド**（LiDAR が当たる形。箱で作る）と **(b) 描画用の形 `.glb`**（Blender をバッチで動かして作る。吊り金具・名札・色）を作る（§3）。どちらも同じ記述の寸法から作るので食い違わない |
| 描く手段 | **R-PY（Python のラスタライザ。CPU だけ）**（§4）。R-GZ（Gazebo のカメラ）は使わない: th の機体モデルに昇降機とカメラを足す必要があり、Gazebo が描き続ける分ノートパソコンの CPU を食う |
| 何が絵を描くか | **描画サービス**が、ss が静止画を求めた時点の「機体の真の位置（Gazebo）＋昇降機の高さ＋カメラの向き」から 1 枚描く（§4） |
| 昇降機とカメラ（`FK-E3`） | **案 A（推奨）: hve の偽物（昇降部の偽物・カメラのソフトの偽物のモード）を使い、静止画の出どころだけ描画サービスに差し替える**（§5）。hve に小さな変更を 3 つ頼む |
| th | **th の Gazebo の起動（`gazebo.launch.py`）に、作ったワールドと機体の置き場を引数で渡す**（th のコードは変えない。画面なしの起動だけ頼む。§6） |
| ss | **本物を、模擬の昇降部とカメラにつなぐ**（ss のコードは変えない。接続先は設定で渡す。§6） |
| 本システム | 段 1〜2 は ss だけを動かして配置図が取れるところまで。**本システムまで通すのは th の 8-g が入ってから**（それまでの扱いは §7 の問い） |
| 測定機構（`FK-E2`） | 最初は「測定機構なし」の道（[-auto.md](DetailedDesign-auto.md) §2.3）。模すのは機構が決まってから |
| 動かし方 | 1 つの compose で 4 つのコンテナ（th の Gazebo・模擬 hve と描画・ss・本システム）。`network_mode: host`・`ROS_DOMAIN_ID` 78（§6） |
| 現場再現版の守り | 記述に `visibility: site` を持たせ、**生成器は site の記述の出力を本システムのリポジトリの中へ書かない**。本システムの試験は、リポジトリの中の記述がすべて `public` であることを確かめる（§8） |

## 1. 構成

```
 シーンの記述（YAML）──生成器──┬─> Gazebo のワールド（箱）──> th の Gazebo（機体・LiDAR）── 機体の真の位置 ─┐
                               └─> 描画用の形（.glb）────────────────────────────────> 描画サービス（R-PY）
                                                                                          ▲    │ 静止画
 ss（本物）──> 昇降部の偽物（hve）── 高さ ─────────────────────────────────────────────┤    ▼
          └──> カメラのソフト（hve・偽物のモード）── 向き ───────────────────────────────┘  /snapshot
 本システム（auto_runner）──> th（段 3 から）／ss
```

| 部品 | 置き場 | 中身 |
| --- | --- | --- |
| シーンの記述 | 広報版: 本システム `fk_ws/src/fk_sim/scenes/`。現場再現版: 非公開リポジトリ（§8） | §2 |
| 生成器 | 本システム `fk_ws/src/fk_sim/fk_sim/scene/`（Python）と Blender のバッチのスクリプト | §3 |
| 描画サービス | 本システム `fk_sim`（ノード）。R-PY は FK-E1 の `tools/fk_e1_render/render_py.py` を元に直す | §4 |
| 模擬 hve | hve の偽物（hve のリポジトリのものを読み取り専用で使う） | §5 |
| th の Gazebo | th の像（`th_ws` の Dockerfile）から別のコンテナで起こす。**`th_robot` コンテナは使わない**（実機作業中のことがある） | §6 |

## 2. シーンの記述

| 欄 | 中身 |
| --- | --- |
| `visibility` | `public` か `site`（§8） |
| `room` | 床の大きさ・壁（線分と高さ）・天井の高さ（昇降機の天井の判定に使う）・床と壁の色 |
| `panels` | 盤ごとに: 中心の位置（x, y）・正面の向き・幅・奥行き・高さ（既定 2.35 m）・吊り金具の有無と位置（既定は四隅）・列（連盤・背中合わせ）・前面の名札の文字（広報版は架空） |
| `obstacles` | 箱（位置・大きさ・向き）。LiDAR に当たる物 |
| `robot` | 機体を置く位置と向き |
| `lights` | 照明（種類・位置・強さ）。描画サービスの既定の強さは FK-E1 で Cycles に合わせた値 |
| `assets`（任意） | 手で作った Blender のファイルを差し込む先（現場の見た目を作り込むとき。現場再現版のリポジトリに置く） |

座標は Gazebo のワールドの座標（m・rad）。盤の寸法の範囲は試作の生成器（`gen_scene.py`）に揃える。

## 3. 生成器

| 出力 | 作り方 |
| --- | --- |
| `world.world`（SDF） | **記述から直接、箱で作る**（壁・盤・障害物）。`gazebo_ros_state` を入れ、描画サービスが機体の真の位置を読めるようにする。見た目は付けない（Gazebo の画面を開く人のために、色だけ付ける） |
| `scene.glb` | **Blender（4.2）をバッチで動かし、記述から盤・吊り金具（JIS B 1168 M20 の実測寸法）・名札・部屋を組んで書き出す**。文字はメッシュにする。手続き的なマテリアルは使わず基本色だけ（FK-E1 で落ちたもの。落としても検出は働いた） |
| `scene.json` | 正解（盤ごとの天面の矩形・吊り金具の 3D 位置）。ss の結果と比べる試験に使う |

- **Blender はシミュレーションの像に入れる**（Linux 版 4.2。描画はしないので CPU だけで足りる）。どの PC でも同じ手順で作れる。
- 出力は `sim_out/scenes/<名前>/`（git に入れない）。記述が変わったら作り直す（記述のハッシュで判断）。

## 4. 描画サービス（R-PY）

| 項目 | 案 |
| --- | --- |
| 受けるもの | 静止画の要求（hve の映像の口の形。§5） |
| 読むもの | 機体の真の位置（Gazebo の `gazebo_ros_state`）・昇降機の高さ（昇降部の偽物）・カメラの向き（カメラのソフトの偽物） |
| カメラの位置 | 機体の位置 ＋ ss の設定と同じ取り付けの値（`camera_height_offset_m`・前後の差・取り付けの角度のずれ `camera_*_offset_deg`・`camera_roll_deg`。ss の `locator.yaml`）。**値は ss の設定を読み、写さない**。こうすると「校正が完全に合っている」状態になる。校正のずれを試したいときは、描く側だけ値をずらす |
| 画像 | 1280×720。**ss の校正の `camera_K` と `camera_dist` で歪ませて描く**（ss はこの歪みを差し引いて位置を出すので、歪み無しで描くと位置がずれる）。FK-E1 の後処理（ノイズと JPEG）を足す。FK-E1 は歪み無しで比べたので、**歪ませた絵でも検出が落ちないことを `WP-SIM-02` で確かめる** |
| 時間 | 1 枚 0.3〜3 秒（FK-E1。デスクトップの CPU）。**ss の画像待ちの上限（`image_timeout_s` 15 s）に収まる**ことを試験で見る |
| 正解との比べ | 描いた 1 枚ごとに、`scene.json` の吊り金具をその視点に投影した正解を残せる（試験・調査用） |

**機体の位置は真値（Gazebo）を使い、th の自己位置推定は使わない**（絵は現実の位置で写るべきなので）。

## 5. 昇降機とカメラ（`FK-E3`）

**案 A（推奨）: hve の偽物を使う。**ss は本物の昇降部・カメラと同じ口で話すので、ss の試験にそのままなる。

| 部品 | 使うもの | hve に要る変更（申し送りの案） |
| --- | --- | --- |
| 昇降部 | hve `tools/fake_lift_server.py`（`/ws/module`・`/ws/ui`。天井・腕の通信の判定まで真似る） | (1) 天井までの距離を、外から（描画サービスがシーンの天井の高さから）与え続けられること（今は `POST /api/fake` で 1 回分） |
| カメラ | hve のカメラのソフトの偽物のモード（`python3 -m hve_camera --fake`） | (2) **偽物のハードウェアのまま、昇降部の偽物（別のプロセス）へつなぐ**モード（今の `--fake` は中に別の偽の昇降部を持つので、ss が見る昇降部と高さが食い違う）。(3) **静止画・映像の出どころを外から差し込める**こと（今は `hve_video` の `/snapshot` を取りに行く。描画サービスがその口に答えれば足りるかを hve に確かめる） |
| 状態の読み出し | 描画サービスが高さと向きを読む | 観察だけの接続（`role: observe`）でカメラの向きが読めるか、hve に確かめる |

**案 B: 本システムが hve の口を真似る偽物を作る**（ss の試験の小さなサーバと同じやり方）。hve を待たずに始められるが、hve の振る舞い（持ち主・止め方・天井）の写しがずれていく。

## 6. 起動（compose）

| サービス | 像 | 起動 | 待ち受け |
| --- | --- | --- | --- |
| `sim_th` | th の像 | `ros2 launch th_bringup gazebo.launch.py world:=<生成したワールド> robot_x:=… robot_y:=… robot_yaw:=… rviz:=false` | th の試験用のポート（§8 の -names.md） |
| `sim_hve` | 本システムの描画の像（FK-E1 の Dockerfile を元に、Blender・pyrender・hve の偽物の依存を入れる） | 昇降部の偽物・カメラのソフトの偽物・描画サービス | 18080（昇降部）・18000（カメラ）（hve の既定の試験用ポート） |
| `sim_ss` | ss の像 | ss の `locator_node`（`lift_host: 127.0.0.1:18080`・`camera_host: 127.0.0.1:18000`・`use_fakes: false`・`hve_lift: true`） | — |
| `sim_fk` | `fk_robot` の像 | 段 3 から（§7） | 試験用のポート（-names.md §6） |

- すべて `network_mode: host`・`ROS_DOMAIN_ID` 78。FastDDS は UDP だけ（th のプロファイル）。
- **th の Gazebo は画面（`gzclient`）を出さずに起動したい**。今の `gazebo.launch.py` は Gazebo の画面を必ず開くので、th に引数を頼む（申し送りの案）。それまでは `DISPLAY` 無しで起こして gzserver だけが残るかを試す。
- **th のシミュレーション用の機体の LiDAR の高さは 0.105 m で、実機（床から 32 cm）と合っていない**（th が記録済み）。盤は背が高いので今回は効かないが、低い障害物の見え方は実機と違う。

## 7. 段階

| 段 | できること | 待つもの |
| --- | --- | --- |
| 1 | 記述から ワールドと `.glb`。広報版の記述 1 本 | — |
| 2 | th の Gazebo を作ったワールドで起こし、**機体を手で動かしながら、ss の `locate_cli` で配置図が取れる**（本物の ss・模擬の昇降部とカメラ・描画サービス） | 案 A なら hve の変更 (2)(3)。案 B なら無し |
| 3 | **本システムまで通す**（選んだ盤を回り、盤前で ss に認識し直させる） | th の 8-g の受け手（本システムの指示で Gazebo の機体が動く）。**それより前に通すかは問い**（下） |
| 4 | 現場再現版（非公開リポジトリの記述で同じものを動かす） | 会場確認・非公開リポジトリ |

**問い（段 3 を 8-g より前に通すか）**: 偽の th（`fake_th`）に、指示を受けたら Gazebo の機体を動かす働きを足せば、8-g を待たずに通せる（動かし方は、目的地へ瞬間移動させるか、th の Nav2 に目的地を渡すか）。ただし本物の th の振る舞いではない。

## 8. 現場再現版の置き場と守り

| 項目 | 案 |
| --- | --- |
| 非公開リポジトリ | 名前はユーザーが決める。中身は現場の記述・手で作った Blender のファイル・現場の写真から作った質感 |
| 渡し方 | 起動の引数 `scene:=<記述のパス>`。非公開リポジトリは本システムのリポジトリの外に置く（例 `../fk-sim-site`） |
| 生成器の守り | `visibility: site` の記述の出力先が本システムのリポジトリの中なら、書かずに止まる |
| 試験の守り | 本システムのリポジトリの中の記述（`fk_ws/src/fk_sim/scenes/**`）がすべて `visibility: public` であること |
| 生成 AI | 現場の記述は、ユーザーが渡した分だけを使う（[Spec-sim.md](../spec/Spec-sim.md) §3）。実装エージェントには広報版だけで作らせる |
