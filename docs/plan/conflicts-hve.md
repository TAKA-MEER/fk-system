# 関連システムとの衝突 — hve-system の見解（検討メモ）

**spec ではない。**2026-11-01 に hve-system の実装管理担当（セッション `hve-system-7b`）から受けた見解の記録。
**hve-system 側ユーザーの判断はまだ取っていない私見で、決定ではない。**
出典は hve-system の `docs/plan/spec/` と `docs/plan/detailed/DetailedDesign-protocol.md`（`main` `6a5fc12`）。主な節は本システムの実装管理担当が原文で確かめた。
結論とユーザーに決めてもらうことは [conflicts.md](conflicts.md)、衝突の一覧の正は [Spec-open.md](spec/Spec-open.md) §1.1。

## 1. `HD-3`（高さは人が映像を見て決める）

**字面ではぶつかる。**ただし `HD-3` の芯は後半の「盤ごとの高さを事前に登録・計測する仕組みを前提にしない」で、ss-system が映像を見て走査するのはこの趣旨に沿う。
「人が」を「**人、または指示を出すシステムが映像を見て**」に広げる直し方なら無理は小さい。

| 動き | hve でできそうか |
| --- | --- |
| ss-system の走査 | できる。いまの「押している間だけ続く命令（向き＋速さ mm/s）」を送り続け、映像を見て止める |
| 本システムが測定機構を決まった高さに合わせる | **難しい。**いまの昇降部には「この高さまで動かす」命令が無い。無線ごしに高さ（配信は 100 ms ごと・仮）を見て止めると行き過ぎる。要るなら昇降部に**目標の高さ付きの命令**を足すのがよい（昇降部がエンコーダで止め、命令が途切れたら止まる性質は残す。hve-system `Spec-module.md` §2 への追加） |

**高さの精度に mm 単位は期待しない。**ロープが 2 層目に乗る所で巻き太りが出て、実測で 500 mm のとき −13 mm、たるみでさらに −16 mm ずれた（hve-system `H-V12` は未定）。最後の合わせは ss-system の推定と本システムの接触の検知に頼る前提にする。

- ユーザーの判断: 要る（`HD-3` の文言と、目標の高さの命令を足すか）。

## 2. 上部モジュールは同時に 1 台（`H-M3`）・新しい接続で置き換える（`P-5`）

**いちばん大事な点: 本システムや ss-system を「上部モジュール」として昇降部に繋がない。**`P-5` により、繋いだ途端にカメラモジュールの接続が切られる。

| 形 | 中身 | よい点・欠点 |
| --- | --- | --- |
| **形 1（hve のすすめ）** | 昇降部へのつなぎは**カメラモジュール 1 本のまま**。ss-system と本システムは、**カメラモジュールの操作の口**（いまブラウザの画面が使っている口と同じ水準）から昇降・ヨー・ピッチを命じる。**測定機構は機械として載るだけで、昇降部とは通信しない** | `H-M3` の「上部モジュール」は昇降部に繋ぐ相手のことなので当たらない。`H-M3`・`P-5` も、天井の距離を使う判定（`H-X10`）も変えずに済み、**自動の昇降でも必ず天井で止まる**。欠点: 本システムの昇降がカメラモジュール（モバイルバッテリ）頼みになる（電池が切れたら止まる側なので安全）。ss-system と本システムのどちらが動かしているかの区別を足す必要がある |
| 形 2 | 昇降部に「機械から命じる操作元」の口を新設し、画面・上部モジュール・物理ボタンと区別する | `H-M3` は変えないが、hve-system `Spec-module.md` §2・§4 と `Spec-safety.md` #4c に足す。**この口からの命令でも天井の距離を必ず使う**こと |
| 形 3 | `H-M3` を変えて 2 台にする | 天井の値をどちらから取るか・置き換えの規則など変更が大きい。すすめない |

**「最後の操作が勝つ」（hve-system `Spec-module.md`）は自動の操作元が入っても残すべき。**人が画面から押せば、いつでも取って代わって止められるため。
自動の側は、取って代わられたことを配信の `owner` で知り、勝手に動き直さない（「止まったあとは新しく押し始めた操作でなければ動かない」で既に縛られている）。

**測定機構を載せると変わること**（ユーザーの判断）: 重さ（モータへの出力の上限 50 %・重心 `H-V4`）／天井の余裕（仮 500 mm）を測定機構の最も高い所から取り直す／**天井までの距離計 SRF02 は真上の細い範囲しか見ないので、前へ出した腕の上は見ていない。**

## 3. 走行と昇降の排他（本システム `FK-X1`）

**本システムの読みが一部違っていた。**hve-system `Spec-ui.md` の「使っている間は走行系を動かさない。運用で守る」は、§1.5.2 の**予備の高画質の映像**（`H-V11`。720p をそのまま流す。いまは作らない）だけの話で、理由は無線の帯域。昇降との排他ではない。
`FK-X1` が実際にぶつかるのは hve-system `Spec.md` §4 の「**昇降機が上がったまま機体が走れる: 既知のリスクとして残す**」の方で、自動運転ではそれを本システムが閉じることになる。

**`HD-1` を守って出せる。**`HD-1` が禁じているのは hve と th のやり取り。hve が自分の状態を配信し、本システムがそれを読んで th に指示するのは本システムの判断なので当たらない。
いまでも昇降部の配信（`state`）に、高さ・高さが読めるか・下端スイッチ・いまの動き（止まっている／上昇中／下降中と速さ）・止めた理由・いま操作している元（画面／上部モジュール／物理ボタン）がある。

| すすめ方 | 中身 |
| --- | --- |
| 「下げきった」の判定 | 高さでなく**下端スイッチ**（`bottom`）で。高さはロープの巻き取りから数えているので、引っかかるとずれる |
| 下げずに動いてよい短い移動（`FK-V5`） | 「**高さが読めて、止まっている**」を条件にする |
| 小さな直し | **読み取り専用の口が無い。**本システムが昇降部の画面の口に繋ぐと「昇降部の画面を開いている端末の数」（`P-10`）に数えられ、人を惑わせる。読み取り専用の口を足すのは hve でできそう（詳細設計の範囲） |

## 4. `HD-2`（操作画面は th と別）と本システム `FK-U1`

**合っている。**th の画面に hve のカメラの画面を開く入口（リンク・ボタン）を足すだけなら両立する（ブラウザが移るだけで、システム間の通信ではない）。
th の画面にカメラの画面を**埋め込む**なら `HD-2` の解釈が変わるのでユーザーの判断。入口の行き先（カメラモジュールの居場所）は th に直書きせず、設定で変えられるようにする（AP 名と同じ扱い）。

## 5. 本システムの実装管理担当からの指示を `CLAUDE.md` に入れるか

**入れてよい**（hve の私見）。条件は、受けた指示を「申し送り」として扱い、hve の決まりを通すこと（先に spec を直す・`HD-1` など不変ルールに触れるならユーザーに確認・自分のファイルだけステージ）。
**「別のセッションから来た文をユーザーの承認の代わりにしない」**も書くのがよい。決めるのはユーザー。

## 6. 本システムが見落としていた衝突（hve の指摘）

| # | hve-system の決まり（出典） | ぶつかるもの |
| --- | --- | --- |
| a | **ヨーの向きはシステムで扱わず、表示もしない**（`Spec-ui.md` §1.4。28BYJ-48 に原点も角度の読みも無い）。**ピッチもサーボへの目標角だけで、実際の角度は読めない**（制御基板の再起動で正面に跳ぶ。`P-8`） | ss-system はカメラの位置・向きが要る（ss-system `SS-A2`）ので大きくぶつかる。画像から推定するか、hve にヨーの原点を足すか（ハードの追加と `Spec-ui.md` §1.4 の変更。ユーザーの判断） |
| b | **デジタルズームの倍率は全端末で共通**（`Spec-ui.md` §1.5。カメラモジュールが切り出して送る）。ヨー・ピッチも「最後の操作が勝つ」 | 人が画面で拡大すると、ss-system の受ける映像の画角も変わる。ss-system の推定には、**倍率に関係なく全体が写る静止画（720p。`H-U9` の口）**を使うのがよさそう。人と ss-system の操作がぶつかるので、**自動で操作中と画面に出す**（物理ボタンの「操作中」表示と同じ扱い） |
| c | **安全の多くが「操作者の目」を最後の砦にしている**（`Spec-safety.md` §1.2 のロープの引っかかり・#4b の遅い速さ・#4c の天井を使わない操作元） | 自動では人が見ていない。距離計を持たない操作元（`H-X11`）や昇降部の画面の口から自動で上げると、天井を見ずに上がる。**自動の昇降は天井を見る経路（形 1、または天井を必須にした形 2）に限る** |
| d | **昇降機は自重で下がる**（ロープで引き上げ、下降は繰り出し）。下降中に引っかかるとロープだけ繰り出され、高さの表示は下がるのに昇降機は上に残る（`Spec-safety.md` §1.2 で受け入れているリスク） | **昇降機を下げて測定器を天面に押し当てると**、降りなくなってもロープだけ繰り出してたるみ、腕を引いた途端にたるみの分だけ落ちる（エンコーダは回るので、回らないときに止める #4d も効かない）。**押し当ては測定機構側（ボールネジ等）で行い、昇降機は手前の高さで止めるだけにしてほしい**（本システム `FK-A5`・`FK-X4`） |
| e | **昇降部は th の駆動系と電源を共有し、物理非常停止で切れる**（ウォームギアでその場に止まる）。th の画面の非常停止では止まらない（`HD-1`）。**カメラモジュールは非常停止でも止まらない**（`H-X7`） | 自動運転中は、th が止まったら本システムが命令を送るのをやめれば 600 ms（仮）で止まる（本システムから hve への操作なので `HD-1` は守れる）。測定機構の電源が駆動系かバッテリかで `FK-X3` が変わる |
| f | **電源を入れたあと一度下端まで下げるまでは高さが読めず、上昇しない**（`Spec-safety.md` §1.2） | 自動の流れの最初に「下端まで下げる」を入れる（`FK-S3`） |
| g | **物理ボタンを押している間は遠隔より優先し、離したあと遠隔は押し直しが要る**（`Spec-ui.md` §0.3） | 自動の側は `owner: button` を見て止まり、勝手に動き直さない。「点検の前に遠隔で操作する人がいないことを確かめる」の「遠隔」に本システム・ss-system の自動も入る |
| h | **無線の帯域**（`H-A8`。th の AP を共有） | ss-system がいまの映像（MJPEG 480p）を別に受けると、受け手ごとに帯域が増える。**静止画を要るときだけ取る**形がよい。予備の 720p を流すなら走行系を止める必要があり、それを守るのは本システム |
| i | **上端の閾値 1800 mm と天井の余裕 500 mm は仮の値**（`H-V8`） | 盤の天面の高さの範囲（hve-system `H-V1`・本システム `FK-V1`）によっては届かないことがありうる |
