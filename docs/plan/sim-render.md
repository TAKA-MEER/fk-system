# 軽い描画で ss-system の吊り金具の検出は働くか（FK-E1）

**問い**: Blender Cycles で描いた合成データで学習した吊り金具の検出器（YOLO pose `lug_v3_s.pt`）は、GPU の無いノートパソコンでも動く軽い描画（R-GZ・R-PY）の絵でも Cycles と同じくらいの検出ができるか。

結論: **どちらも Cycles と同等の検出ができた**。R-GZ は検出率 1.000、R-PY は 0.985（Cycles 自身も 1.000）。1 枚の描画時間は R-GZ が約 0.03 秒、R-PY が 0.3〜3.1 秒（シーンの重さ次第）。**まずは R-PY を勧める**（Gazebo を介さず単独で動く。R-GZ は速いが、変換の手間が多い）。

## 次にやること

1. **どちらを使うかは詳細設計で決める**（2026-11-22 実装管理担当。R-PY は単独で動き組み込みが軽い。R-GZ は LiDAR と同じ Gazebo の中で描けて速いが、変換の手間が多い。どちらも検出は働く）。
   実装管理担当が R-PY の 1 シーンを描き直し（画素の差ほぼ 0・時間も一致）、自分の集計で 3 組の検出率（Cycles・R-PY・R-GZ）を再現した（2026-11-22）。
   **注意**: 露出（光源の強さの既定値）はこの 20 シーンの Cycles の明るさに合わせて決めた。シーンも学習データと同じ生成器から作ったので、確かめたのは「描き方の違い」だけで、現場の見た目での検出は別の問題
2. 学習データに軽い描画の絵を混ぜるかは、ss-system 側の判断（ここでは案として記録する。FK-E1 の範囲外）。
3. シーン・視点数を増やす（今回は単盤・連盤×電気室・工場の 20 視点のみ。歪みありの絵は今回対象外）。
4. R-GZ を使う場合は、`.glb` から `obj_parts` への変換（[詳細](sim-render-results.md)）が必須で、直接の `.dae`・Blender の `.obj` は使えない。
