# Spec-open — 関連システムとの関係・未確定事項・決定の記録

[Spec.md](Spec.md) の詳細。**何が決まっていないか**はここが正。
決まったら §3 に 1 行記録し、該当する Spec ファイルへ反映してから §2 の行を消す。

ID の付け方: 本システムの未確定事項は `FK-<分類><番号>`（th-system の `O-a1`・`F-` 系、hve-system の `H-` 系と衝突させないため）。
分類は `G`（目標）・`S`（範囲）・`A`（構成）・`U`（画面）・`V`（値・測定）・`X`（安全）。
決定した設計思想は `FD-<番号>`。

## 1. 関連システムとの関係

**本システムは th-system・hve-system に指示を出し、情報を取得する**（2026-10-30 ユーザー決定）。
**写しより相手の原文が正。**相手のリポジトリはここから編集しない（CLAUDE.md「th-system・hve-system との境界」）。

### 1.1 相手側の決まりごとで、本システムの決定とぶつかるもの

| 相手の決まりごと | 本システムの決定 | 扱い |

## 2. 未確定事項

### 2.1 目標と範囲

| ID | 問い | これが決まると決まるもの |
| --- | --- | --- |
| **`FK-S2`** | **膜厚・板厚の測り方。**何の膜・板か（測る点は [Spec.md](Spec.md) §1.1 で決定）、精度、使う測定器と本システムとのつなぎ方、結果をどう残し・誰に渡すか。「同じ操作」（`FD-3`）の中で両者に違いが要るか（測定器の切り替え等） | 使う機器・情報・画面・保存 |
| **`FK-S3`** | **2 つのモードの残り**（流れは [Spec.md](Spec.md) §1.1.1・§1.1.2 で決定）。走査しても天面が見つからない・推定が外れたときどうするか（測らずに知らせる等）。盤前に複数の盤（連盤）が写るとき、立会でどの盤の中央を測るか。「画像認識に最適な画角」とは何か（高さ・向き）。測る前に推定した点を人が確かめるか。「右から順に」の右はどこから見た右か（配置図の上か、盤の正面に向かってか）。途中で止まったとき、測り終えた点・盤をどう扱うか。5 点のあいだのクローラの動かし方（その場で旋回するか、横へずれるか）と、それに要る位置の精度 | 画面・指示の範囲・安全の水準 |
| **`FK-S5`** | **自律測定の地図。**起動直後に作る配置図と、LiDAR の地図をどう重ねるか。カメラの届かない盤は配置図に載らない（[検証レポート](https://claude.ai/artifact/A3Pz8dbXUn2srTn8NQFq2J)）ので、移動中に配置図を足すか。推測で引いた経路の先に障害物があったときに止めるのは th-system の停止（`FD-2`）でよいか。前日の試験場内地図（th-system）を使うか、毎回作るか | th-system への申し送り（§1.2）・安全 |
| **`FK-G1`** | 本システムの目標は何か。th-system の G1（人・物への接触 0 件、意図しない挙動 0 件。他のすべてに優先）を本システムにも課すか。設計思想（th-system SD-1〜SD-9）を引き継ぐか | すべての設計判断の優先順位 |
