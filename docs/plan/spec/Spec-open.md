# Spec-open — 関連システムとの関係・未確定事項・決定の記録

[Spec.md](Spec.md) の詳細。**何が決まっていないか**はここが正。
決まったら §3 に 1 行記録し、該当する Spec ファイルへ反映してから §2 の行を消す。

ID の付け方: 本システムの未確定事項は `FK-<分類><番号>`（th-system の `O-a1`・`F-` 系、hve-system の `H-` 系と衝突させないため）。
分類は `G`（目標）・`S`（範囲）・`A`（構成）・`U`（画面）・`V`（値・測定）・`X`（安全）。
決定した設計思想は `FD-<番号>`。

## 1. 関連システムとの関係

**本システムは th-system・hve-system に指示を出し、情報を取得する**（2026-10-30 ユーザー決定）。
**写しより相手の原文が正。**相手のリポジトリはここから編集しない（CLAUDE.md「th-system・hve-system との境界」）。

### 1.1 相手側の決まりごとで、本システムの決定とぶつかるもの

| 相手の決まりごと | 本システムの決定 | 扱い |
| --- | --- | --- |
| hve-system `HD-1`: **th-system から独立させる。通信しない・走行禁止などの連動も設けない**（不変ルール。変えるならユーザーに確認して先に hve-system の spec を直す） | 本システムが走行系と昇降機の両方に指示を出す。**走行の指示は本システムが出し、hve-system は走行を指示する権限を持たない**（`FD-2`） | **解決**（2026-10-30。`FK-A3`）: `HD-1` は**変えない**。hve-system は th-system と直接やり取りせず、走行と昇降を組み合わせる判断は本システムが持つ。**hve-system には本システムからの指示の受け口が要る**（§1.2） |
| hve-system `HD-2`: 操作画面は th-system と別 | 走行系の画面を主とし、そこからカメラの画面へ移る（`FD-1`） | 画面を別に保ったまま入口だけ足すなら両立しうる。**確かめてから決める**（`FK-U1`） |
| hve-system [Spec-ui.md](../../../../hve-system/docs/plan/spec/Spec-ui.md): カメラの画面を使っている間は走行系を動かさない。**操作者の運用で守る**（信号で止めない） | 自律測定では人が見ていない | **未解決**（`FK-X1`） |
| th-system [Spec-onsite.md](../../../../th-system/docs/plan/spec/Spec-onsite.md) §7.2: 昇降・撮影側との正式インターフェースは未確定で、**仮で「作業中」ボタンを置く**（th-system `O-a6`） | 本システムが走行系に指示を出し、情報を取る | th-system `O-a6` の答えの一部になりうる（`FK-A1`） |

### 1.2 相手側に要る変更（申し送り）

**ユーザーの指示があるまで相手のリポジトリは触らない。**指示が出たら、相手の `CLAUDE.md` に従い先に相手の spec を直す。

| 相手 | 要る変更 | 根拠 |
| --- | --- | --- |
| th-system | 画面からカメラの画面・本システムの画面へ移る入口 | `FD-1` |
| th-system | 本システムからの指示の受け口と、情報の出口 | §1 |
| hve-system | 本システムからの指示の受け口と、情報の出口（`HD-1` は変えない。th-system とは直接やり取りしないまま） | §1・§1.1・`FD-2` |

## 2. 未確定事項

### 2.1 目標と範囲

| ID | 問い | これが決まると決まるもの |
| --- | --- | --- |
| **`FK-S2`** | **膜厚・板厚の測り方。**何の膜・板か、どこを測るか（盤のどの位置・何点）、精度、使う測定器と本システムとのつなぎ方、結果をどう残し・誰に渡すか。「同じ操作」（`FD-3`）の中で両者に違いが要るか（測定器の切り替え等） | 使う機器・情報・画面・保存 |
| **`FK-S3`** | **2 つのモードの違い。**立会試験中の測定は誰が何を操作し、本システムはどこまで自動でやるか。自律測定は人が何をし、どこから先を任せるか | 指示の範囲・安全の水準・画面 |
| **`FK-G1`** | 本システムの目標は何か。th-system の G1（人・物への接触 0 件、意図しない挙動 0 件。他のすべてに優先）を本システムにも課すか。設計思想（th-system SD-1〜SD-9）を引き継ぐか | すべての設計判断の優先順位 |

### 2.2 構成

| ID | 問い | 選択肢の例（決めていない） |
| --- | --- | --- |
| **`FK-A1`** | **各システムに何を指示し、何を取るか**（走行系・昇降機・カメラそれぞれ） | 走行系: 盤前への移動・到着・状態 ／ 昇降機: 高さ ／ カメラ: 向き・撮影・映像。**具体的な手段は詳細設計** |
| `FK-A2` | 使う道具（言語・ファームウェア・画面）と、それぞれの試験方法 | 決まったら `CLAUDE.md`「ビルドとテスト」に書く |
| `FK-A4` | 本システムはどこで動くか（PC・ラズパイ・その他） | — |

### 2.3 画面

| ID | 問い | 関係 |
| --- | --- | --- |
| **`FK-U1`** | 走行系の画面から移る先（カメラ・本システム）は別の画面のままか、走行系の画面の中に組み込むか。戻り方・非常停止の見え方 | hve-system `HD-2`・th-system SD-3（非常停止は常に動作し何にも覆われない） |

### 2.4 値・測定

`FK-S2` が決まってから立てる。

### 2.5 安全

| ID | 問い | 関係 |
| --- | --- | --- |
| **`FK-X1`** | **走行中に昇降機を上げない・昇降機が上がっている間に走らせないことを、本システムがどう保証するか**（走行の指示は本システムが出す。`FD-2`）。人が th-system・hve-system の画面から直接操作したときとの競合をどう扱うか | hve-system は操作者の運用で守っている（§1.1）。自律では人が見ていない |
| `FK-X2` | 本システムが落ちた・通信が切れたとき、指示を受けていた各システムはどうなるか | 相手側のウォッチドッグ（th-system 600 ms ほか） |
| `FK-X3` | 非常停止（物理・画面）で本システムの自動測定も止まるか | th-system・hve-system の非常停止 |
