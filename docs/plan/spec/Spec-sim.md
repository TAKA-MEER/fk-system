# Spec-sim — 自律測定のシミュレーション環境

**自律測定の一連の動作を、実機なしで確かめるための環境**（2026-11-22 ユーザー決定）。
実装（ノード名・ファイル構成・描画の手段の名前）は書かない。詳細設計に回す。
決まっていない所は [Spec-open.md](Spec-open.md) §2.6 の ID を付けた。**推測で埋めない。**

| 項目 | 決まっていること | 出典 |

## 2. 2 つの種類

| 種類 | 中身 | 置き場 |
| --- | --- | --- |
| **現場再現版** | **実証実験の現場を再現する**（盤の配置・寸法・部屋・見た目） | **非公開の別リポジトリ**（本システムを含む 4 リポジトリは公開なので、そこへは入れない） |
| **広報版** | **現場再現版から、公開できない情報を抜いたもの** | 公開してよい（本システムのリポジトリ） |

- **2 つは同じ作り方で作り、違うのは現場の中身（配置・寸法・見た目）だけにする**（片方だけ直って食い違うのを防ぐ。2026-11-22。作り方を分けるかは詳細設計で変えてよいが、この性質は守る）。
- **広報版で何を抜くか**は未定（`FK-E4`）。会場確認シート（hve-system [会場確認シート](../../../../hve-system/docs/現場確認/会場確認シート.html)）で項目ごとに決める**公開範囲**に従う。

## 3. 現場の情報の扱い

| 決まり | 出典 |
| --- | --- |
| **現場再現版の中身は、公開リポジトリに入れない。**コミットの前に、公開リポジトリへ現場の情報が混ざっていないことを確かめる | 2026-11-22 ユーザー |
| **現場の情報を生成 AI に入れるかは、ユーザーが判断して入れる。**AI（実装管理担当・実装エージェント）は、ユーザーから渡された分だけを使い、自分から現場の情報を取りに行かない | 2026-11-22 ユーザー |
| 判断の手がかりは会場確認シートの「生成AI への入力」の印（先方と決める） | hve-system 会場確認シート p.1 |

## 4. 動かす PC と描画

| 決まり | 出典 |
| --- | --- |
| **本番のノートパソコン（GPU なし。th-system と同じ PC）でも動くことを目指す** | 2026-11-22 ユーザー |
| **盤・部屋の形と見た目は Blender で作る。ただし絵を描くのは Blender の描画ではなく、軽い別の方法にする**（ノートパソコンでも動かすため） | 2026-11-22 ユーザー |
| LiDAR が当たる形と、カメラに写る形は**同じ元から作り、食い違わない**ようにする | 2026-11-22（§2 の性質から） |
| **軽い描画の絵でも、ss-system の吊り金具の検出は Blender の描画（Cycles）の絵と同等に働く**（`FK-E1`。GPU なしで描いて、同じシーンの 20 視点で検出率 0.985〜1.000。[sim-render.md](../sim-render.md)）。描く手段は詳細設計で選ぶ。確かめたのは描き方の違いだけで、現場の見た目での検出は ss-system の実物での確認の側 | 2026-11-22 スパイク |
